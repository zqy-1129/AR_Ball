### 安装

```bash
adb install -r GuideSphere.apk
```

首次启动需授予相机权限（拒绝也可运行，会退化为「引导球 + 渐变底」）；
授予权限后会先看到三页引导，看完才正式开始采集。
本包为**演示签名**，正式发布请用自有密钥重新签名（做法见根 README 第三节）。

## 二、演示视频里能看到什么

> 时间轴对应 `guidesphere_demo.mp4`（约 36 s）。

1. **00:00 – 00:10 首次引导。** 全屏遮罩上依次出现三页图文：
   `① 把物体放进取景框` → `② 绕着物体缓慢转一圈` → `③ 8 个面全亮就完成`。
   点哪都翻页，右上角「跳过」直达；第 3 页的按钮变成青绿色的 **「开始扫描」**。
   注意这期间左上角覆盖度始终是 **`0%`（已拍 0/8 个面）** —— 引导期间采集被刻意冻结，
   所以首次启动的进度是从真正的 0 开始，而不是「一打开就已经拍了 1/8」。
2. **00:10 – 00:34 绕物体水平转一圈。** 相机实时画面铺满全屏（模拟器内置合成场景），
   画面底部停靠一个**灰色底色**的半透明引导球（菲涅尔边缘光 + 经纬网格线），
   球面按 **8 个方位扇区整面铺开点阵**（每面 3 列 × 7 行 = 21 点，共 168 点）。
   镜头每转到一个新的面并稳定停留 `≈0.22 s`（自动采样），**该面的 21 个点整面一起点亮**；
   覆盖度按 `+1/8` 跳，左上角同时弹出「已捕获 +N」浮动提示，**手机震一下**。
   引导是分层给的：
   - 球面上**目标面整片琥珀高亮**（哪一片还没拍）；
   - 球外**琥珀方向箭头** + 中央一句人话指令（`向右转 / 向左转 / 抬高手机 / 压低手机`）；
   - 对准过程中环外那段**细弧**从 0 涨到满，中央文字切换为 `已对准 · 保持不动`；
   - 环上 **8 段进度**一段一段变绿，左上角的 8 个小方块同步。
3. **00:34 – 00:36 收尾。** 覆盖度到达 `100% / 已拍 8/8 个面`，8 段环全绿，
   顶部弹出 **「360° 无死角覆盖完成 / 可以提交给三维重建算法了 / 点按此处重新扫描」**，
   底部状态变为「全部覆盖 ✓」。全程 `60 FPS`。

> 视频在**模拟器**上录制（相机画面是模拟器内置的合成场景），但**姿态解算、整面覆盖判定、
> 覆盖率统计、60 FPS 渲染全部是真实的运行时行为**，不是播放动画。
> 姿态来自模拟器控制台**注入的真实加速度计 / 磁力计读数**，走的是 App 真实的传感器代码路径。
> 之所以不在真机录，是因为一加 PKX110 的 ColorOS 封禁了 `adb shell screenrecord` 写文件
> （原因与排查过程见[实现文档 §八](../docs/IMPLEMENTATION.md)）。

## 三、验证记录

### 3.1 模拟器（720×1600，`-gpu host`）

| 项目 | 结果 |
| --- | --- |
| 帧率 / 单帧 | **60 FPS**，`drawMs` 0.07 ~ 0.2 ms |
| 球体停靠 | `rPx=122`、`cy=1088` = `1600 × 0.68`，与真机同比例 |
| 绕物体环绕 | 单圈水平环绕一次性到达 **100%（168/168，8/8 个面，零补扫）**，约 24 s |
| 面捕获 | 每正对一个新面 `lit` 精确 **+21**，8 次到 168：`21 → 42 → 63 → 84 → 105 → 126 → 147 → 168` |
| 首次引导 | 冷启动展示三页，`pm clear` 后重现；引导期间 `cov=0%`（采集已冻结），走完三页后自动恢复自动采样 |
| 对齐进度（`dwell`） | 连续采样到 `7% → 22% → 37% → 53% → 75% → 83% → 90% → 100%`，填满即整面点亮 |
| 对准进度弧（像素度量） | 连拍 30 帧，环带 `r ∈ [151,160] px` 的青色度 `(G+B)/2−R` 在其中 5 帧跃升到 `≈148`（其余 `≈ −14`），确认这段 0.22 s 的瞬态弧确实按预期渲染 |
| 完成横幅 | `100%` 时弹出；**点按横幅整块命中并重新开始**（`cov` 立即回落并从 0 重新累积） |
| 重置防误触 | 第一次点击后胶囊变为琥珀色「确认重置」，覆盖度**保持不变**；2.5 s 内未再点则自动撤防 |
| 优化后回归 | 逐面步进复测 8 步全对，`faces=8/8`，无回退 |

### 3.2 真机（一加 PKX110 / Android 16 / SDK 36 / arm64-v8a / 1080×2344）

> 下表为**上一版视觉**（蓝色球壳 + 中央 8 段环 + 140 点）的实测记录。
> 渲染管线与绘制量级相同，性能与生命周期结论对当前版本仍成立；
> 新版视觉（灰球 + 168 点阵 + 分层引导）的**真机复测待设备接入后进行**。

| 项目 | 结果 |
| --- | --- |
| 冷启动 | 约 56 ms 进入引导页 |
| 帧率 / 单帧 | 稳定 **60 FPS**，0.3 ~ 0.8 ms |
| 崩溃 | 无 |
| 相机预览 | CameraX 后置实时画面作为背景，正常 |
| 姿态来源 | 静置 20 s 采样 60 次，**60/60 全部为「陀螺仪姿态」**，零翻转 |
| 传感器事件 | 旋转矢量实测约 89 Hz（`dumpsys sensorservice` 计数 1332 events / 15 s） |
| 球体停靠 | `rPx=184`、`cy=1593` = `2344 × 0.68`，上方画面完整留给被摄物体 |
| 生命周期 | HOME 回前台、息屏/亮屏、连续重复启动，渲染线程数恒为 1，无泄漏 |

### 3.3 已知未验证项

- **触觉反馈的真机手感**：模拟器没有振动马达，`Haptics.available` 为 false，三档震动在
  模拟器上全部静默降级 —— 逻辑分支已走通（无异常），但**震动强度与节奏的真机手感未验证**。
  需要的话调 `ui/Haptics.kt` 里的 `tick / faceCaptured / allDone` 三个方法。
- **新版视觉的真机复测**：灰球 + 168 点阵 + 分层引导尚未在真机上跑过（设备未接入）。
- **非 ColorOS 机型的录屏**：演示视频仅在模拟器录制，未在其他真机上验证录屏链路。
- **极端俯仰**：一次拍摄只判定方位面，上下两极的覆盖不进判定；若需要「上/下也各算一个面」，
  需要按根 README 第八节的说明扩展扇区划分。

## 四、复现方式

```bash
# 1. 启动模拟器（无显示环境要加 -no-window，否则会弹阻塞式对话框；-gpu host 是 60fps 前提）
emulator -avd GuideSphere -gpu host -no-boot-anim

# 2. 安装并启动（清掉数据可重新触发首次引导）
adb install -r GuideSphere.apk
adb shell pm clear com.remy.guidesphere && adb shell pm grant com.remy.guidesphere android.permission.CAMERA
adb shell am start -n com.remy.guidesphere/.MainActivity

# 3. 注入真实的加速度计/磁力计读数，绕物体水平转一圈
python ../.tools/drive.py sweep 1 3 0 1 "8"

# 4. 看覆盖度遥测
adb logcat -s GuideSphereStats:I
# I GuideSphereStats: cov=100.0% lit=168/168 faces=8/8 cam=6 target=5 dwell=0% fps=60 drawMs=0.07 rPx=122 cy=1088 next=(0.00,0.00) src=陀螺仪姿态

# 一键：安装 → 引导 → 环绕 → 闭环补扫 → 录屏 → 拉回 mp4
python ../.tools/record_demo.py <apk路径> <输出mp4路径>
```

> `record_demo.py` 会先 `pm clear` 再 `pm grant`，**顺序不能反** ——
> `pm clear` 会把运行时权限一并撤销，反过来的话整段演示都会被「需要相机权限」遮罩盖住。

`.tools/` 下的脚本依赖本机 Python 与 adb，**不参与 App 构建**。
